### Edge v127+ App-Bound Encryption 关键发现（2026-07-22 更新）
- Edge 版本 ≥ v127 引入 **App-Bound Encryption**（`app_bound_encrypted_key`，`APPB` 前缀），旧的 `encrypted_key`（`DPAPI` 前缀）解出的 AES key **无法解密 v20 Cookie**。
- `APPB` 密钥需 Edge 服务身份解密，本地离线无法拿到（error 13 / RPC_S_CALL_FAILED）。
- 所有第三方库（browser_cookie3 0.20.1、pycookiecheat 0.8.0）均受影响，报 "MAC check failed"。
- **DPAPI 本身在沙箱内可用**（CryptProtectData/UnprotectData 往返成功），但 APPB 不走标准 DPAPI。
- **唯一可靠方案**：手动粘 `li_at` Cookie 值（F12 → Application → Cookies → .linkedin.com → li_at）。
- `linkedin_collector.py` 已更新：自动尝试三种解密路径（v10_key → direct_DPAPI → browser_cookie3），全部失败则引导手动粘贴并缓存到 `li_session.json`。
- `web-article-collector` 技能文档已更新：新增「三·一 Edge v127+ App-Bound Encryption」章节。

## LinkedIn 实跑成功（Playwright persistent_context 复用登录态）

**时间**: 2026-07-22 11:25-12:03

### 背景
用户要求"控制电脑操作"，并建议用 Web Access(CDP)。但本机 Edge 未开远程调试；沙箱 127.0.0.1 被禁，CDP 走不通。最后改用 Playwright `launchPersistentContext` 复用 Edge profile，在沙箱内实跑成功。

### 关键步骤
1. 启动 Edge 带 `--remote-debugging-port=9222` + 临时 user-data-dir（让用户在当前窗口登录 LinkedIn）。
2. 登录完成后，杀掉该 Edge 进程（释放 profile 锁）。
3. 用 Playwright `chromium.launchPersistentContext(temp_profile, { channel: 'msedge', headless: false })` 重新打开同一个 profile。
4. 导航到 `linkedin.com/company/gasturbinehub/posts/?feedView=all`。
5. 自动关闭"公司主页将查看您的访问记录"弹窗。
6. 慢滚动 6 次加载更多动态，然后回到顶部抽取。

### 交付
- `linkedin_gasturbinehub.json`: 13 条动态结构化数据（id/time/text/images）。
- `linkedin_gasturbinehub.md`: 可读 Markdown 汇总。
- `linkedin_gasturbinehub.png`: 页面截图。
- `collect_linkedin.js`: 可复用的 Node.js 采集脚本。

### 经验
- Playwright persistent_context 比 CDP 更适合本沙箱：它通过 child process pipe 与浏览器通信，不依赖 localhost；CDP 需要 127.0.0.1 连接，被沙箱阻断。
- 必须先关闭占用 profile 的 Edge 才能 `launchPersistentContext`，否则报 profile lock。
- LinkedIn 公司页弹窗（访问记录）会遮挡但不妨碍 DOM 抽取；主动点击"继续前往公司主页"后页面更干净。
- 图片过滤：排除 `company-logo` 等头像类 URL，只保留 `media.licdn.com` 的真实 feed 图片。
